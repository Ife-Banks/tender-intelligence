STAGE B REQUIREMENT COMPLETENESS SUMMARY

FINDING ADDRESSED
-----------------
"Current validation can compare model-supplied requirements with model-supplied
assessments without independently establishing that the requirement set is complete."

MECHANISM
---------
The pipeline uses a two-pass approach in VerdictEngine.generate():

  Pass 1 — Independent requirement extraction
    - Separate LLM call with only tender documents (no KB, no company data)
    - Output: RequirementExtraction { requirements: [MaterialRequirement] }
    - Each MaterialRequirement carries: requirement text + source evidence
      (document_id / location / exact quote from the real document)
    - Validated by _validate_requirement_sources:
        - Source evidence must cite real text at real locations
        - No empty or duplicate requirement texts

  Pass 2 — Assessment against the established set
    - Input includes material_requirements from Pass 1 as authoritative
    - Output: VerdictPayload with assessments list
    - Validated by _validate_semantics:
        - set(payload.requirements) == set(established)       [no omissions, no additions]
        - set(assessed requirements) == set(established)      [no missing, no orphans]
        - Each assessment includes its Pass 1 source evidence [provenance preserved]
        - incomplete_inputs flag must match the bundle
        - Unsupported assessments must say "no evidence on file"
        - Verdict derived deterministically from assessment statuses

COMPLETENESS RULES THAT PREVENT THE ATTACK VECTOR
--------------------------------------------------
1. Model omits R3 from requirements list       → REJECTED (set equality)
2. Model omits R3 assessment                   → REJECTED (set equality)
3. Model adds R99 (not in established set)     → REJECTED (set equality)
4. Model strips source evidence from R1        → REJECTED (provenance coverage)
5. Model claims complete when bundle failed    → REJECTED (incomplete_inputs mismatch)
6. Model makes unsupported absence claim       → REJECTED ("no evidence on file" required)
7. Verdict label inconsistent with statuses    → REJECTED (deterministic verdict check)
